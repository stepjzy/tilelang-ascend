### 2.2 C 侧逐行 gather（单行动态索引 GM→L1）

- **现象**：p7（整行 [1,576]→kv_l1[j,:] + 整 K gemm）max_abs 4.48e+01（p7_run4.log）；p7b（架构精确形态：3 列段 buffer + 标量行 + clamp + 3 段 QK + PV）QK 4.13e+01 / PV 3.85e+01（p7b_run.log）——均为 O(1) 垃圾，**执行完成、无挂死/无 aicore exception**（与 p4/p6 的 timeout 形态本质不同）。
- **dump 细读（p7b_kernel_source.cc L49-61，判定依据）**：
  1. **静态区域形态正确（同 kernel 同原语对照）**：L49-52 `copy_gm_to_l1<bf16,64,256>(q0_l1[0], Q_bf16[0], 576, 64, 256, true)`——模板参 = 拷贝区域形状，与运行时 m=64/n=256 一致；生产代码同形态（v2 L1398-1402 ws_kv 静态区域整块读，本轮复核）在用且正确（56/0 全量精度间接实证）。
  2. **单行动态形态参数自相矛盾**：L55 `copy_gm_to_l1<bf16, 256, 256>(v0_l1[(g*256)], KV[clamp(idx0)·576], (seq_len_kv*576), 1, 256, false)`——① 模板 `<256,256>` 取**整 buffer** 高度而非 1 行切片（与运行时 m=1 失配；静态形态模板恒等于拷贝区域形状）；② dst 偏移 `g*256` / `(g*256)+16`（L59）——正确值应为 (16g+j)·256 = 4096g+256j，发射值 = (16g+j)·**16**，即行索引乘了**组大小 GRP=16** 而非行宽 256（步长推导错误，偏移小 16×）；③ 运行时 src_stride/m/n 本身正确——错的只有模板形状与 dst 偏移。
  3. **标量侧正常**：L54 `Indices.GetValue((g*16))` + 三元 clamp 链生成正确（log.md「坏死在拷贝参数推导」实证）。
- **分类：编译器缺陷**（DSL/lowering 对"GM 标量动态行索引 + 单行切片"的 copy 模板参/dst 偏移推导坏死）。**非 MTE 硬件对动态 L1 目的寻址的限制**——判据：发射参数静态可见地自相矛盾（①②），且带错参数的指令被执行完成（MTE 接受并执行、返回垃圾），硬件行为未被隔离触及（p4/p6 式挂死才是硬件拒绝形态）。
- **次级问题（如实标注：未验证）**：即使参数推导修复，m=1 写入 NZ 分形布局 L1 的非 16 行组对齐偏移是否被 MTE 支持**仍未验证**——GM→L1 splice 先例（testing/python/language/test_tilelang_ascend_language_gm_to_l1.py，Groups 3/5/7/9）只证 16 行组粒度；gather 行散列无法成组 → 大概率仍不可行，但此为"未达硬件验证的次级问题"，不改变主分类（编译器层）。
- **判别标准（供后续复用）**："动态行索引"（本条：每行基址来自 GM GetValue + clamp、区域 1 行——坏死）vs "静态区域整块"（ws_kv→L1：区域形状/偏移可静态推导、slot 仅线性平移——正确在用）。
- **若解除需**：框架修复单行动态 copy 的模板参/偏移推导（前端/lowering）**且**原语层验证 m=1 或成组 NZ 对齐散写（后者与 gather 语义矛盾，大概率无解）——解锁条件是"编译器修复 ∧ 硬件验证"双重门槛。

### 4.3 C. 结论：<24288us 是否可达（按证据三档，不粉饰）

**① 已证不可达（证据闭合，无需再试）**：全部**单 kernel** 组合。流量地板 = 全 dtype 20.20GB > 达标流量上限 18.0GB（24.288ms×0.74TB/s，保守体制封顶带宽）；带宽侧达标需持续聚合 ≥0.83TB/s（20.20GB 地板口径；C1 口径 23.42GB 需 0.96TB/s）——单 kernel 混合流体制实测两代封顶 [0.68, 0.74]，1.33 仅在 ≤14.8MB 驻留 + 无散射流条件成立（v2 工作区 50.5MB 不满足）。**流量与带宽双口径同时封死**。含 A2a/A2b/A5 的任何组合流量 ≥ C1 同级（A2a 净省仅 1.27GB 且同步退化——v1 同会话慢 10.7% 实证），同样封死。

**② 边界情形（唯一贴线通道）**：C5/C6（双 kernel 拆分 + dtype + 同步瘦身）。证据带定标墙 ~21-33 / ~19-30ms，**中位 24-26ms 贴线但中位不在线下**。≤24.288 需以下前提**同时**成立：
- (a) kernel A（纯 gather）≤~6ms：KV 池 4.7MB 在 ws_kv 写流下保持 L2 驻留（L2 写策略未证实）；
- (b) kernel B 持续 ≥0.91TB/s 于**真实 50.5MB 环集**——nogather 的 ≥910GB/s / 1.33TB/s 证据产自 stale 14.8MB 驻留集，**证据缺口**；若 B 落两锚间无证据区 0.75-0.9 → C5=26-30ms 仍超；
- (c) B 相同步重构不劣化（F0 族消失是净收益，F1A/F2/F3 重排待验证）；
- (d) dtype 谓词通过目标数据（bnd_extreme 级回退）+ ws_o bf16 余量复测（C6 另需 ws_s fp16 的 Lse 余量实测）；
- (e) 双 launch + workspace 跨 kernel 开销 ≪1ms；
- (f) 快态窗口（慢态机器态一切 +18%）。
(a)(b) 为无直接实证的带宽假设。**概率评估：大概率不可达——贴线依赖 2 项未证实假设同时落在乐观半区，且证据带中位在线上**。

**③ 建议**：
- 若继续投入，路线优先级序：**① A1a+A1b dtype 安全包**（确定性最大：−8.35GB → 预期墙 ~28-36ms，vs 快态基线 −20~40%；谓词+回退成对；R-UB-LAYOUT 单项 A/B）→ **② 拆分前置探针 ×2**（一天量级，放 /tmp/opencode/audit2/ 或后续会话：纯 V gather kernel 实测 BW_A；22GB 级混合负载于真实 50.5MB 工作区实测 BW_B——两数落定即闭合 C4/C5 判定，避免 rev 级工程沉没；任一落保守半区 → 拆分终止）→ **③ A3a LEAD 加深**（−2~4ms，低风险，可与 ① 并行）。
- 若终止，定位陈述：v2 55258us（慢态口径）/46667us（快态干净基线）= A2 平台强制 GM 中转（18.25GB，§2 分类：硬件/编译器多层封死无绕过）+ a3 实现额外（7.52GB）在实测聚合 [0.68, 0.74]TB/s 上的**带宽饱和解**（墙 ≈ 流量/带宽，§1.3 闭合）；24288us 在单 kernel 体制需流量 ≤18.0GB（< 全 dtype 地板 20.20GB）或持续带宽 ≥0.83TB/s（> 实测上限 12-22%）——双口径证据封死；唯一未闭合通道（双 kernel 拆分 + 全 dtype）证据带中位 24-26ms 贴线、依赖 2 项未实证 L2 驻留假设——**大概率不可达，直说**。Stage 1 重定标建议：目标带调整至 ≥30ms 量级（C2 稳健可达带 26-34ms），或以 A5 平台为前提重立直连架构（§2.1a 解除条件：消 ws_kv 往返 9.66GB + 复活 P 驻留免 ws_p 2.15GB + 免 F0 族）。
