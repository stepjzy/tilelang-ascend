## 3. G1（golden BI128 = 364.7us）完整分解

| 分量 | us | 占比 | 数据流 |
|------|-----|------|--------|
| **C 引擎（ws 读回 302MB + gemm）** | **328** | **90%** | ③ ws_kv GM→L1（架构强制，形态无关） |
| C/V 耦合（握手+填充/排空） | 28 | 8% | 跨核协议 |
| launch | 8.4 | 2% | runtime |
| **V 行读** | ~236 | 隐藏于 C 之下 | ① 源行读（256 行 L2 热，顺序描述符） |
| **合计** | **364.7** | 100% | |

**三条字节流分解**：
| 流 | 字节 | 引擎/率 | 时间 | 数据形态依赖 |
|----|------|---------|------|-------------|
| ① 源行读（V: GM→UB） | arange/randint: 同 256 行 L2 热；描述符 262K | MTE2 描述符率（顺序 ~36ns vs 乱序 ~48ns） | ~236(arange)/~315(randint) | **是（描述符顺序）** |
| ② **ws_kv 写（V: UB→GM）** | **302 MB** | MTE3 ~16-33 GB/s/AIV | 隐藏于 C 读回 | **否（架构强制）** |
| ③ **ws_kv 读回（C: GM→L1）** | **302 MB** | MTE2 ~46 GB/s/AIC（脏 burst） | **328** | **否（架构强制）** |

## 4. 逐点瓶颈归因

| 点 | 主导墙 | 效率比 | 差距原因 |
|----|--------|--------|---------|
| G1 | **C-ws（328us = 90%）** | 101% | 贴地板——通用索引架构的 ws 302MB GM 往返为不可绕过成本 |
| G2 | C-ws（419us = 88%） | 96% | BI32 的 ws 脏 burst 率更低（36 vs 46 GB/s）+ 块数 4×（412 vs 103）摊销差 |
| G3 | C-ws + V-row 近均衡 | 83% | V ≈ 315 ≈ C ≈ 328 → 耦合放大 105us（F0 等待 + 管线填充） |
| G4 | C-ws + V-row | 88% | V ≈ 374 vs C ≈ 419 → 部分解耦 |

**G1 vs G3 差距（77us）归因**：**全部来自耦合解耦，非 V 提速**。
- G3: 441.7 = C_eng(328) + coupling(105) + launch(8.4)——V≈C 近均衡 → F0 等待放大
- G1: 364.7 = C_eng(328) + coupling(28) + launch(8.4)——V(236) 远低于 C(328) → C 独走
- Δcoupling = 77us = **arange 解耦红利**（V 顺序描述符率使 V 提前完成，消除 C 侧 F0 等待）

## 5. 解决方案（逐墙分级）

### 已封死（Phase 1-4 实证判死，引用会话结论）

| 路径 | 判死证据 | 引用 |
|------|---------|------|
| R2 手工 gemm 流水（消 C 头 drain） | 生产 A/B +12.7%（chunk 脏填充惩罚 > 重叠收益） | Phase 4 |
| R5 AIC 直采（消 ws 往返） | r_aic=100ns/行（>80ns 阈值）+ 总账 ≥420us | Phase 4 spike_r5 |
| ws 往返消除（反转 = Q 来到 KV 侧） | Q 重载墙 158-248us/核 + 散射原子 202ns/op + 分桶 ≥100us | Phase 2 spike |
| m_tile dense（L0C→UB fixpipe 消 score 往返） | A2 无 L0C→UB fixpipe（API 级缺失） | Phase 2/4 |
| O4 块内热行去重 | 对 arange/randint 同 pool（256 行已全 L2 热）——**去重无额外收益**（去重下限 = 现状） | 本轮分析 |

### 数据形态特化路径（新分析，模式特化）

**条件**：索引跨任务高度重复（arange 类 / 真实 DSA sink-token 场景）。

**方案**：模式检测（host 或 on-device 检查 indices 是否 ≈ 共享 panel）→ 特化 kernel：
1. 256 行共享 KV 面板一次性载入 L1/UB（288 KB）
2. score = 小 dense GEMM Q[2048,16,576] × KV_panel[256,576]^T（每任务 [16,576]×[576,128]）
3. **完全跳过 ws_kv 302MB 往返**——V 不需逐槽位 gather，C 直接从常驻面板计算

**预期收益**：364.7 → ~48us（theoA 级，7.6× 提升）→ **220us PASS**

**风险与限制**：
- 仅对 arange/共享模式成立——对通用 randint 散射无收益（需回退通用路径）
- 需模式检测或调用方保证（检测错误的代价 = 沉默错误结果）
- 属于"模式特化"而非通用优化——leader 须判断是否纳入交付边界

### A5/950 原生 gather

- 硬件 gather_gm_to_ubuf + SIMT MGather：消除 V 侧描述符瓶颈（① 源行读 ~236→~50us）
- **但 ws_kv 302MB 往返仍在**（架构选择而非硬件限制）→ 预期仅 ~330→~330（C-paced 不变）
- 需同时配合 ws 消除（反转或 L0C→UB）才能突破 220us

### 验收线重议

- 220us = 0.5× H20 GPU 预估（110us）——910B3 通用索引架构地板 ~365us（arange golden 最优情况）
- **220us 在 910B3 通用索引架构下不可达**（论证见下节）

## 6. 220us 可达性论证（拼装地板）

```
220us 线
  ├─ C 引擎（ws 302MB 往返 @ 46GB/s×20）─ 328us ← 唯一硬地板（数据形态无关）
  ├─ V 行读（arange L2 热 ~236us）← 隐藏于 C 下（非限制）
  ├─ launch 8.4us
  └─ 系统 = max(C, V) + coupling ≥ 328 + 8.4 = 336us（V 完全解耦极限）
                                                    ↑ 仍 > 220us（1.53×）
```

**结论：220us 不可达**——即使 V 完全解耦（coupling=0），C 侧 ws 302MB 往返引擎时间 328us > 220us。消除 ws 往返的全部已实证路径（R2/R5/反转/m_tile）均已判死（§5.1）。唯一剩余路径 = 数据形态特化（§5.2，模式限定）或 A5/950 硬件代际。

## 8. 不确定性声明

1. **V arange 描述符率 ~36ns/行**（=randint 48.1×0.75）：估算（±20%），基于顺序 vs 乱序 MTE2 描述符效率差的合理推测；不影响主导墙判定（V 在 G1 隐藏于 C 下）。
2. **C 引擎 328us**（BI128）：由 G1 实测反推（364.7 - coupling 28 - launch 8.4）；ws 率 46GB/s 来自 msprof 校准。BI32 的 419us 含 ws 率降低（36GB/s）与 gemm 摊销恶化两个估算项。
3. **coupling 28-105us**：从实测与 C_eng 差值反推，无独立测量。arange vs randint 的 coupling 差异（77us）为稳健推论（两配置 C 引擎相同、系统差 = coupling 差）。
4. **theoA 47.6us**：假定 256 行全 L2 常驻 + CV 完美重叠。cube 率 158.4 TFLOPS 来自单点 msprof 校准（±10%）。V-vec 率 2.51 elems/ns 来自生产 msprof（N_val 相近，可信度高）。
5. **G3 复测 441.7 vs 历史锚点 426.7**（+3.5%）：varlen offsets（本轮）vs 单 batch（历史）+ 会话漂移；不影响 G1 判定（G1 为独立测量）。
