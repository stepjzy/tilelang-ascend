## 0. 结论速览

| 项 | 结论 |
|---|---|
| **联合瓶颈结构** | **共享 L2 服务带宽联合受限**：官方 arange 口径总 GM 侧流量 ~995MB，实测聚合服务率上限 ~2.96-3.0TB/s（真实 kernel 本身即观测最高点）→ **带宽地板 ≈ 333µs，当前 kernel 贴地运行**（会话带 335.7-381.5µs） |
| **旧门控的真实身份** | gemm_v0 尾部 MTE2 自门控 + F0/F1 节拍 = **隐式带宽仲裁器，且实测优于自由跑**（节拍 2.96 vs 自由 2.57TB/s）——P1 解门控回退的物理机制 |
| **"V 引擎和≈墙钟"反信号解读** | V 引擎 99.5% 占空比是 **L2 服务占用**（DMA 在途/背压计入 busy），非引擎硬件极限——V solo 23.5ns/行 vs 联合 45.3ns/行（K2 vs K3）证明 |
| **52.7/55.3GB/s 的身份** | 均为仲裁均衡下的**条件有效带宽**（solo C 读 = 130.2GB/s 干净 / ~128 脏行≈干净——"46GB/s dirty 天花板"证伪为条件值） |
| **P2（SIDE_PAIR=False）** | **官方口径实测 -1.53%**（配对双轮一致）+ 精度 5/5 torch.equal + V overlap 1.031→1.102 + C 读率 55.3→59.8——**可采纳候选**（机制 = V 锯齿发射流平滑 → 仲裁间隙利用提升） |
| **220µs 距离** | 需聚合 ≥4.5TB/s（1.5× 观测上限）或流量减 1/3（三腿 302MB 消除路径全封死 + K5 证明同字节重塑无效）→ **官方口径下 220 不可达；现实区间 333-360µs**；开放角度如实列出（§4.3） |

## 1. 联合瓶颈模型重构（官方 arange 口径）

### 1.1 带宽账本（每 kernel 调用，S=2048/H=16/topk=128/BI=128）

| 流量腿 | 字节 | 路径 | 证据 |
|---|---|---|---|
| V 行读（gather 源，128 行×1152B×2048） | 302MB | L2 命中（arange: 147KB 唯一行全热；L2Cache.csv AIV 读命中 99.6%） | msprof+结构 |
| V bulk 写（ws_kv 中转） | 302MB | L2 脏行写入 | 结构 |
| C ws 读回 | 302MB | L2 脏行读（AIC 读命中 91.3%） | msprof |
| Q 读 + ws_acc×2 + 输出 + idx/lse | ~95MB | 混合（Q 37.7MB 冷流） | 结构 |
| **合计（全过 L2，含 DRAM 支线）** | **~995MB** | — | — |

聚合服务率实测包络（本会话，graph-replay/msprof 交叉）：

| 配置 | 聚合率 | 说明 |
|---|---|---|
| **真实 kernel（flag 仲裁节拍）** | **2.96TB/s**（995MB/335.7µs，probes 进程） | **观测最高点** |
| K3 自由联合骨架（无 flag，双侧自由跑） | 2.57TB/s（902MB/353.2µs） | **自由跑反而更低** |
| K1 C 单侧 bulk 读（20 AIC，L2 驻留） | 2.63TB/s（读单流） | solo 130.2GB/s/核 |
| K2 V 单侧流（行读+bulk 写） | 1.07TB/s | solo 23.5ns/行（固定地址） |
| P1（C 解门控，ablation 配对） | 端到端 +4~6% 回退 | 聚合率下降（推算 ~2.8） |

**核心结论：L2 对该混合流量的可观测服务上限 ~2.96-3.0TB/s，且 flag 节拍仲裁是迄今最优的调度方式**——真实 kernel 的仲裁把 V 锯齿（SIDE_PAIR 串行）与 C 门控（gemm 尾 flag）交错成了比自由跑更高的聚合效率。这不是巧合而是 P1 证伪的机制：解门控让 C 突发读撞进 V 的服务窗口，双侧率同降（K3 分侧实证：C 130→87.3GB/s、V 23.5→45.3ns/行）。

### 1.2 "V 引擎和 ≈ 墙钟"反信号的消解（R9 重解读）

R9 反信号（V 引擎和 375.8 ≈ 墙钟 375.5，generic_pipeline_analysis §1.5）此前有两种竞争解释：① V 引擎硬件饱和；② 共享带宽联合受限。本轮裁决为 **②**：
- K2（V solo，固定地址无寻址链）：整流 2.77-3.01µs/块——若 V 引擎是真饱和，加回寻址链（+0.5-0.65µs/块）后应 ≈ 实测引擎和 3.65µs/块 ✓ 数值自洽；
- 但 K3（V 与 C 自由并发）：V MTE2 busy 295.7µs @99.5% 占空比而行服务 45.3ns/行（solo 的 1.9×）——**busy 时间被 L2 服务排队拉长，"饱和"是服务受限的投影**；
- 两侧各自的自恰节拍（C 3.54µs/块 ≈ V 3.54µs/块）在旧门控下恰好相抵 = 仲裁均衡点，而非独立巧合。

### 1.3 旧门控"节奏价值"的量化

| 仲裁方式 | 端到端 | 聚合率 |
|---|---|---|
| 旧门控（现状：gemm 尾 MTE2 自门控 + F0/F1 + SIDE_PAIR） | 335.7µs（probes 进程基准） | 2.96TB/s |
| 无仲裁自由跑（K3 代理） | 353.2µs | 2.57TB/s |
| P1 解门控（C 突发，V 节拍不变） | +4~6% 回退（ablation 配对） | ~2.8TB/s（推算） |
| P2 平滑 V（仲裁结构不变，去 V 侧锯齿） | **-1.53%** | ~3.0TB/s（C 读率 +8% 佐证） |

**门控节奏价值 ≈ 17µs（353→336）/ ~15% 聚合率**——"完全仲裁（旧）"已近最优，"完全解门控（P1）"最差；**改进空间只在"更平滑的仲裁"（P2 方向），不在"更少的仲裁"（P1 方向）**。

## 2. 后续方向裁决表

> 校准原则（P1 教训）：任何单侧优化预期必须过**联合 bound 检验**——在 2.96TB/s 聚合上限下，"给一侧松绑"若不减少流量、只改变时序，收益上界 = 仲裁间隙的回收（实测包络 ~0-5%），且方向错误时为负（P1 +4~6%）。

| 方向 | 证据 | 系统级预期 | 风险 | 验证成本 | 裁决 |
|---|---|---|---|---|---|
| **P2（SIDE_PAIR=False）** | 本轮官方口径配对 -1.53%（双轮一致）+ 精度 5/5 exact + 机制链完整（V overlap↑、C 读率↑） | **-1.5%**（已含联合效应） | 低（1 行，自然排空余量 5× 已 spike 双口径验证） | 已完成 | **✅ 可采纳**（唯一已验证正收益） |
| **P2b（LEAD=3 发射点前移）** | V 寻址/发射链 ~0.5-0.65µs/块（引擎和 3.65 vs K2 solo 2.8-3.0）；F1 标量门控是第二把锁（上轮 spike 实证） | **-1~-3%**（回收发射链的一部分；V 是数据路径绑定，收益上界=issue 链非引擎） | 中（assert 放宽 + prologue side 冲突保护 + OFFSET_N=3 标量窗） | ~0.5-1 天 spike | **可攻击，次优先**（在 P2 之上叠加） |

| **连续性快路径（arange 检测→bulk 读）** | K5 数据路径证伪：同字节 bulk 化 -1.6%；仅省寻址链（≈P2b 等价） | **-1~-3%**（= P2b 的特化版，且仅对结构化索引生效；random 口径 0） | 中（检测分支+双路径维护） | 中 | **不推荐**（与 P2b 同收益但加特化复杂度；且属用户已否定的特化方向邻域） |

## 3. 220µs 距离的诚实评估（官方 arange 口径）

### 3.1 联合 bound 下的现实区间

| 层 | 值 | 依据 |
|---|---|---|
| 当前官方锚点 | **359.6µs**（回退后复测）/ 364.7（记录锚） | G6 harness |
| 本会话带 | 335.7（probes 进程）- 381.5（P2 bench 进程） | 进程热态 ±7%（如实披露） |
| 带宽地板 | **~333µs**（995MB / 2.96TB/s 观测上限） | §1.1 账本+包络 |
| P2+P2b 后 | ~322-350µs | 配对推算 |
| **220µs** | 需聚合 **4.52TB/s**（1.52× 观测上限）或流量 **≤651MB**（-35%） | 算术 |

### 3.2 差距构成（113-140µs）

- **架构性（实证封死）**：三腿 302MB 的消除路径——R2 手工流水（+12.7%）、R5 AIC 直采（100ns/行）、Q 反转（重载墙+散射原子）、L0C→UB fixpipe（A2 无 API）、P1 解门控（+4~6%）全部判死；K5 新证：**同字节重塑（bulk 化/描述符整形）无效**——数据路径绑定；
- **条件性（会话/状态）**：~7% 进程热态带（335.7-381.5）；
- **可回收（调度级）**：~0-5%（P2 已收 1.5%；P2b 余量 1-3%）——**不足以改变量级**。

### 3.3 开放角度（不预判硬件下界——按用户明令区分两层）

- **当前架构预测极限**：~333µs（= 带宽账本/观测聚合上限；P2+P2b 后 ~322-327µs 是当前结构下可期待的最好值）；
- **硬件理论下界（未定）**：本报告的 2.96TB/s 是**该流量混合+该访问形态下的观测包络**，非硬件常数——以下角度未穷尽、如实列为开放：① L2 服务率是否对其他混合比（如读写比例、行粒度分布）有更高点（未系统扫描）；② 是否存在未被 tilelang 暴露的 L2 驻留/逐出提示原语可改变脏行逐出行为（S=4096 超线性提示容量敏感存在）；③ 更高层的流量消除（topk 语义/算法层去重、稀疏格式变化）超出算子层权限；
- **用户已排除的方向**：panel/共享模式特化（arange 检测→L1 常驻面板，曾实测 143µs PASS）——本报告尊重该决策，仅记录其存在。

## 5. 不确定性声明

1. **聚合上限 2.96TB/s 是观测包络非硬件常数**：来自真实 kernel 自身的最高观测；未做混合比扫描（§3.3 开放角度如实列出）；"硬件理论下界"明令不预判；
2. 进程热态带 ±7%（335.7-381.5µs 同一代码不同进程）——所有相对结论均同进程配对；绝对值仅锚定参考（沿用 ablation 纪律）；
3. msprof 相对差（P2 -5.5%）与配对差（-1.53%）不一致，机制性指标（overlap/读率）与配对方向一致故采信，时序幅度以配对为准；
4. K1-K5 骨架为物理代理（固定地址、无寻址链/无 gemm/无算法），用于界定引擎/路径极限，与真实 kernel 的差值含寻址链等真实成本；K2 两次运行 282-307µs（±8% 骨架级漂移，取区间）；
5. P2b 预期（-1~-3%）为模型推算未实测（结构改动量 ~0.5-1 天，含 assert 放宽与 prologue side 冲突保护的正确性风险）；
